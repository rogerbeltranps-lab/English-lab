# Teaching materials index

Everything Roger needs to teach and assess each course, in one place. Pick the course, then the Learning Situation (LS). Nothing here is for students: they use the site.

**Where each kind of material lives**

| Material | Where |
|---|---|
| Teaching programme (all six LSs of a course) | `docs/<course>/programme.md` |
| Grammar and vocabulary per LS | end of each programme, plus a study PDF per route inside the LS2 site folders |
| Beginners (A1) grammar and vocabulary | last chapter of each programme |
| LS design (content, routes, assessment) | `docs/<course>/ls<n>-<name>/` |
| Final product rubric | `final-product-assessment.md` in the LS docs folder; the rubric students see is on the final product page |
| Practice exam | the LS site folder, `sample-exam.html` |
| Real exams and answer keys | **Google Drive > Feina > Teacher Studio**, in each LS's `Exam` folder, not in this repo (the repo is public, so students could read them) |

Site links below open the live site (sign in as teacher). Doc links open the file here on GitHub. Roger's private Drive copy (Word programmes, exams, keys, audios, LS listenings, assessment docs and rubrics, Google Forms scripts, competences, levels, the Lexora word list) is in **Teacher Studio**, sorted the same way: [00 Start here](https://docs.google.com/document/d/1nJ9d1Geg6jy3j9oI0Ns2N0dZ7EkpTBwiapL6ENl7JdY/edit) links every folder.

## Docs map (for building the site)

Start with the [root AGENTS.md](../AGENTS.md): it holds the rules for every course and LS. Then open the course and LS you are working on.

```
docs/
  README.md                      this index; add each new LS's row when its docs folder is created
  general/                       not tied to a course or LS
    roadmap.md                   planned clean-up of the code structure
    tasks.md                     living list of pending site tasks
    new-ls-playbook.md           how we build a new LS: checklist for Roger + technical notes (model: 4ESO LS2)
  4eso/
    programme.md                 Roger's 4ESO teaching programme (all 6 LS, grammar and vocabulary per LS, Beginners chapter)
    ls1-my-real-routine/
      AGENTS.md                  rules and dated decisions for this LS
      overview.md                the course content (three routes)
      assessment-criteria.md     activities mapped to the assessment criteria
    ls2-seasons-and-celebrations/
      AGENTS.md
      overview.md
      assessment-criteria.md     activities mapped to the assessment criteria
      competences-grid.md        competences × activities, and when each criterion is marked
      final-product-assessment.md  groups, parts, steps, marks and rubric of the final product
      indicators.md              NA / AS / AN / AE indicators per LS criterion
      grading.md                 LS mark, evidence per criterion and how levels are collected
  2eso/
    programme.md                 Roger's 2ESO teaching programme (Learning Situations 2n ESO, 21 Oct 2026, rev. 24 Oct)
    ls1-my-real-routine/
      AGENTS.md
      overview.md
      assessment-criteria.md     activities mapped to the assessment criteria
    ls2-free-time-live/
      AGENTS.md                  rules, how it was built from 4ESO LS2, and the dated decision log
      overview.md                the course content (three routes)
      assessment-criteria.md     activities mapped to the eight LS criteria
      competences-grid.md        competences × activities, and when each criterion is marked
      final-product-assessment.md  the individual Free Time Vlog: routes, steps, marks, two rounds
      indicators.md              NA / AS / AN / AE indicators per LS criterion (generated from el-grading.js)
      grading.md                 LS mark, evidence per criterion and how levels are collected
  archive/                       old drafts, for reference only
```

**For each new LS:** follow [general/new-ls-playbook.md](general/new-ls-playbook.md). In short: create `docs/<course>/ls<n>-<name>/` with an `AGENTS.md` (rules for that LS plus a dated decision log) and an `overview.md` (the approved content), and fill in its row in the course table above. Decisions that apply to every LS go in the root AGENTS.md; decisions for one LS go in its own AGENTS.md.
